Organiser II Data pack Architecture (TechRef Chapter 9)

Data packs are removable solid-state storage modules for the Organiser II. Unlike disk drives, Data packs have no sectors or absolute cluster tables. The file system is a sequential stream of variable-length records navigated by relative length walking.

1. The 24-Bit Addressing Model (PK$SADD §9.5.8)

For packs larger than 64KB (such as 128KB, 256KB, and 512KB), the Data pack file system natively uses a 24-bit linear address:

Accumulator B    : High 8 bits (PKB_HPAD, $91)
Index Register X : Low 16 bits (PKW_CPAD, $92)

Example from official manual:
LDA B,#$1      ; High byte
LDX #$2345     ; Low 16-bit word
OS  PK$SADD    ; Sets pack address to $12345 (128K/512K pack)

2. 16KB Segmented Hardware Architecture (TechRef §9.2.2.3 & Flashpack Spec)

A 512KB Flash Datapak consists of 32 segments of 16KB each (address lines A14–A18 written to the on-pack segment register). Inside each segment, address lines A8–A13 select 256-byte pages, and A0–A7 select byte offsets. The ROM service PK$SADD automatically calculates the segment, page, and byte toggles.

3. Why File ID Collisions Are Fatal

Data files (Type 0x81) assign an internal 1-byte File ID ($90–$FF). Individual records belonging to that file are tagged solely with that File ID. If multiple files share the same ID, the Organiser OS will interleave all matching records into the same field buffer, corrupting data in OPL programs.

4. Procedure Header & Body Framing

In Psion Organiser II OPL, every procedure is stored as a pair of records: a Procedure Header (Type 0x83) declaring the procedure name, immediately followed by a Long Record Wrapper (Type 0x80) containing the procedure's compiled object code length ($L_{\text{code}}$) and optional source code text length ($L_{\text{src}}$). If $L_{\text{code}} + L_{\text{src}} + 4 \le \text{payloadLen}$, the procedure makes structural sense on the pack.
